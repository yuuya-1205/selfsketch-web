# 学習計画

このリポジトリは、2026-09-17 に全消去して作り直した SelfSketch の Web アプリです。
作り直しの目的は「アプリを完成させること」ではなく、以下の技術を **1 本のアプリを通して学ぶこと** に置きます。

## 学びたいこと

- Next.js で Web フロントエンドを書く
- Go でバックエンドを書く
- RDB（PostgreSQL）の設計と運用
- インフラ全般。特に AWS と Docker
- Python でデータ分析ができるようになる
- 市場価値の高い技術を学び、今後も続く学習習慣をつける

これらは 1 つの構成にそのまま収まります。

```
Next.js（画面） → Go（API） → PostgreSQL
        └── Docker Compose でローカル起動
        └── AWS に配置
        └── たまった実データを Python で分析
```

## 進め方の原則

- **同時に新しいことを 2 つ以上始めない。** フェーズごとに「新しい技術」を 1 つに絞る
- **1 機能を縦に貫通させて終わらせる。** 画面だけ、API だけを大量に作らない
- **終わりが見える単位で区切る。** 各フェーズに完了条件を置き、終わったら次へ進む
- PR とコミットは細かく分ける。1 コミットは単体でビルドが通り、単体で revert できる最小単位
- 学んだことは `docs/` に残す。フェーズごとに学習ログを書く

## フェーズ

### 0. 土台と習慣づくり（新しいもの: Docker）

- Docker Compose で PostgreSQL を立てる
- リポジトリ構成、AGENTS.md、CI の最小形を作る
- 学習リズム（例: 週 1 PR）と学習ログの置き場を決める

完了条件: `docker compose up` で DB が立ち、CI が main で緑になる。

### 1. RDB と Go（新しいもの: RDB 設計）

- アプリの題材に沿ってテーブルを設計し、マイグレーションを書く
- Go から PostgreSQL を叩く API を 1 本作る
- 8 項目の中で一番土台に効くのが RDB なので、Next.js より先に置く

完了条件: 1 リソースの CRUD が API として動き、テストが通る。

### 2. Next.js（新しいもの: App Router）

- React 経験があるので飛距離が一番小さい
- App Router、Server Components、Go API との接続、認証を学ぶ

完了条件: フェーズ 1 の API を使う画面が 1 つ動き、ログインできる。

### 3. AWS（新しいもの: クラウド配置）

- Docker 化したものを AWS に配置する
- まず ECS Fargate か App Runner と RDS。慣れたら Terraform で書き直す
- 料金が発生する唯一のフェーズ

完了条件: 公開 URL からアプリが使える。

### 4. Python でデータ分析（新しいもの: pandas / Jupyter）

- アプリの DB にたまった実データを pandas と Jupyter で読む
- 「自分のデータ」なので学習題材として続きやすい

完了条件: DB から取り出したデータで 1 つ分析ノートブックを書く。
