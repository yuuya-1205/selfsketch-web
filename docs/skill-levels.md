# 学べるスキルと目標レベル

このプロジェクトで学べるスキルの一覧。スキルごとに「どのレベルまで持っていくか」を決めるために使う。
決めた目標は各表の「目標」欄に書く。計画全体は [learning-plan.md](./learning-plan.md) にある。

## レベルの段（全スキル共通）

| レベル | 名前 | できること |
| --- | --- | --- |
| L1 | 触れる | 既にあるものを読み、手順どおりに動かせる |
| L2 | 作れる | 一から自分で書ける、組める |
| L3 | 設計できる | いくつかの案を比べて選び、選んだ理由を文書に書ける |
| L4 | 運用できる | 遅さ、障害、費用を測り、回し続けられる。料金計算もここに入る |
| L5 | 改善提案できる | 数字を根拠に改善案を出せる。人の成果物をレビューして教えられる |

例: CI の「設計、運用、料金計算、改善提案」までできる状態は L5 にあたる。

## スキル一覧

「上限」は、このプロジェクトの中で届く一番上のレベル。一人開発で実際のユーザーがいないため、
運用（L4）が疑似体験で止まるものもある。

### 開発の進め方

| スキル | フェーズ | 上限 | 目標 | 上限で何ができるか |
| --- | --- | --- | --- | --- |
| TDD | 0〜 | L5 | | 古典派とロンドン派を使い分けられる。進め方を他の人にレビューで指導できる |
| テスト設計 | 0〜 | L5 | | テストの配分、テストダブル、E2E を壊れにくくする工夫、契約テスト、ミューテーションテスト、プロパティベーステスト。テストの質を数字で示して改善を提案できる |
| AI 駆動開発 | 0〜 | L5 | | AGENTS.md とスキルの設計、AI に任せる範囲の判断、スプレッドシート → md → スキルでテストを実装する流れ |
| Git と PR の運用 | 0〜 | L4 | | 細かく分けたコミット、ブランチ保護、revert しやすい粒度。チームがいないので L5 は届きにくい |

## 目標を決めるときの注意

- **全部を L5 にはできない。** 週 30 時間の中では、L5 にできるのは 3〜4 個が現実的。
  計画で深く掘ると決めているのはテストと CI なので、残りは L3 を基本にすると見積もりと合う
- **上限は固定ではない。** 例えば Go を L4 まで上げるなら、負荷試験やプロファイリングの作業を足す。
  そのときは learning-plan.md の見積もりも一緒に直す
- **L5 の「人に教える」は一人だと届きにくい。** 学習ログやブログに書くことで代わりにする
