### 「ログイン」 シーケンス図

- 前提：ログインしていない
- 終わりの状態：
  - 成功: ログインが完了している（続きは「今日の画面を開く」の図）
  - 失敗: エラーでログイン画面のまま

```mermaid
sequenceDiagram
   actor ユーザー
   participant ブラウザ
   participant ページ
   participant 仮API
   ユーザー->>ブラウザ: リンクを押す
   ブラウザ->>ページ: ログイン画面をリクエストする
   ページ-->>ブラウザ: ログイン画面を返す
   ブラウザ-->>ユーザー: ログイン画面を表示する
   ユーザー->>ブラウザ: メールアドレスとパスワードを入力する
   ユーザー->>ブラウザ: ログインボタンを押す
   ブラウザ->>ページ: メールアドレスとパスワードを送る
   ページ->>仮API: ログインを確かめてほしいと頼む（メールアドレスとパスワードを渡す）
   alt ログインに成功した
      仮API-->>ページ: 成功を返す
      ページ-->>ブラウザ: 今日の画面へ移るように返す
      Note over ブラウザ,ページ: 続きは「今日の画面を開く」の図
   else ログインに失敗した
      仮API-->>ページ: 失敗を返す
      ページ-->>ブラウザ: エラーメッセージを付けてログイン画面を返す
      ブラウザ-->>ユーザー: 「メールアドレスかパスワードが違います」と表示する
   end
```

### 「今日の画面を開く」 シーケンス図

- 前提：ログイン済み
- 終わりの状態：今日の習慣の一覧が表示されている。ログインが切れていたらログイン画面、習慣がなければ「習慣がありません」の画面で終わります
- フェーズ1で扱わない部品：今日のスケッチ、連続記録、1年後の自分、今日の一言・気分、今週の達成率

```mermaid
sequenceDiagram
   actor ユーザー
   participant ブラウザ
   participant ページ
   participant 仮API
   ユーザー->>ブラウザ: 今日の画面を開く
   ブラウザ->>ページ: 今日の画面をリクエストする（ログインの印を付けて）
   ページ->>仮API: ログインしている人のユーザー情報を頼む
   alt ログインが切れていた
      仮API-->>ページ: ログインしていないことを返す
      ページ-->>ブラウザ: ログイン画面へ移るように返す
      ブラウザ-->>ユーザー: ログイン画面を表示する
   else ログインしている
      仮API-->>ページ: ユーザー情報を返す
      ページ->>仮API: ログインしている人の今日の習慣を頼む
      alt 習慣があった
         仮API-->>ページ: 今日の習慣の一覧を返す（名前・完了・完了時刻・時間帯）
         ページ-->>ブラウザ: 習慣の一覧が入った今日の画面を返す
      else 習慣が1つもない
         仮API-->>ページ: 空の一覧を返す
         ページ-->>ブラウザ: 「習慣がありません」を入れた今日の画面を返す
      end
      ブラウザ-->>ユーザー: 今日の画面を表示する
   end
```

- 空の一覧を返すことにした理由
  毎回nullチェックするのはめんどくさい。nullチェックを忘れることはあるので。
- 同時ではなく、順番に頼むことにした理由
  ログインが切れていたらわざわざ習慣を呼ぶ必要がないから順番にした。
- 「今日」を誰が決めるかは、まだ決めていないこと
  今は「未決。API 契約で決める」
