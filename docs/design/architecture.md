### 目標

### 「ログイン」 シーケンス図

- 前提：ログインしていない
- 終わりの状態：
  - 成功: ログインが完了している（続きは「今日の画面を開く」の図）
  - 失敗: エラーでログイン画面のまま

```mermaid
sequenceDiagram
   actor ユーザー
   participant ブラウザ
   participant ページ
   participant 仮API
   ユーザー->>ブラウザ: リンクを押す
   ブラウザ->>ページ: ログイン画面をリクエストする
   ページ-->>ブラウザ: ログイン画面を返す
   ブラウザ-->>ユーザー: ログイン画面を表示する
   ユーザー->>ブラウザ: メールアドレスとパスワードを入力する
   ユーザー->>ブラウザ: ログインボタンを押す
   ブラウザ->>ページ: メールアドレスとパスワードを送る
   ページ->>仮API: ログインを確かめてほしいと頼む（メールアドレスとパスワードを渡す）
   alt ログインに成功した
      仮API-->>ページ: 成功を返す
      ページ-->>ブラウザ: 今日の画面へ移るように返す
      Note over ブラウザ,ページ: 続きは「今日の画面を開く」の図
   else ログインに失敗した
      仮API-->>ページ: 失敗を返す
      ページ-->>ブラウザ: エラーメッセージを付けてログイン画面を返す
      ブラウザ-->>ユーザー: 「メールアドレスかパスワードが違います」と表示する
   end
```

### 「今日の画面を開く」 シーケンス図

- 前提：ログイン済み
- 終わりの状態：今日の習慣の一覧が表示されている。ログインが切れていたらログイン画面、習慣がなければ「習慣がありません」の画面で終わります
- フェーズ1で扱わない部品：今日のスケッチ、連続記録、1年後の自分、今日の一言・気分、今週の達成率

```mermaid
sequenceDiagram
   actor ユーザー
   participant ブラウザ
   participant ページ
   participant 仮API
   ユーザー->>ブラウザ: 今日の画面を開く
   ブラウザ->>ページ: 今日の画面をリクエストする（ログインの印を付けて）
   ページ->>仮API: ログインしている人のユーザー情報を頼む
   alt ログインが切れていた
      仮API-->>ページ: ログインしていないことを返す
      ページ-->>ブラウザ: ログイン画面へ移るように返す
      ブラウザ-->>ユーザー: ログイン画面を表示する
   else ログインしている
      仮API-->>ページ: ユーザー情報を返す
      ページ->>仮API: ログインしている人の今日の習慣を頼む
      alt 習慣があった
         仮API-->>ページ: 今日の習慣の一覧を返す（名前・完了・完了時刻・時間帯）
         ページ-->>ブラウザ: 習慣の一覧が入った今日の画面を返す
      else 習慣が1つもない
         仮API-->>ページ: 空の一覧を返す
         ページ-->>ブラウザ: 「習慣がありません」を入れた今日の画面を返す
      end
      ブラウザ-->>ユーザー: 今日の画面を表示する
   end
```

- 空の一覧を返すことにした理由
  毎回nullチェックするのはめんどくさい。nullチェックを忘れることはあるので。
- 同時ではなく、順番に頼むことにした理由
  ログインが切れていたらわざわざ習慣を呼ぶ必要がないから順番にした。
- 「今日」を誰が決めるかは、まだ決めていないこと
  今は「未決。API 契約で決める」

### 「習慣を作る」 シーケンス図

- 前提：ログイン済み、今日の画面が表示されている（「今日の画面を開く」の図の終わり）
- 終わりの状態：
  - 作成した: モーダルが閉じ、新しい習慣が今日の一覧に出ている
  - キャンセルした: モーダルが閉じ、今日の画面のまま
  - 入力が不正だった: モーダルのままエラーが表示されている
  - ログインが切れていた: ログイン画面
- 入力する項目：
  - 習慣の名前
  - 頻度（デフォルトは毎日）
  - 時間帯
  - 所要時間
- フェーズ1で扱わない部品：「1年後の自分」に紐づける

```mermaid
sequenceDiagram
   actor ユーザー
   participant ブラウザ
   participant ページ
   participant 仮API
   ユーザー->>ブラウザ: 習慣を追加ボタンを押す
   ブラウザ-->>ユーザー: 新しい習慣のモーダルを表示する
   ユーザー->>ブラウザ: 名前・頻度・時間帯・所要時間を入力する
   alt キャンセルを押した
      ユーザー->>ブラウザ: キャンセルを押す
      ブラウザ-->>ユーザー: モーダルを閉じる
   else 習慣を作成を押した
      ユーザー->>ブラウザ: 習慣を作成を押す
      ブラウザ->>ページ: 入力した内容を送る（ログインの印を付けて）
      ページ->>仮API: 習慣を作ってほしいと頼む（名前・頻度・時間帯・所要時間を渡す）
      alt 作れた
         仮API-->>ページ: 作れたことを返す
         ページ->>仮API: ログインしている人の今日の習慣を頼む
         仮API-->>ページ: 今日の習慣の一覧を返す（新しい習慣を含む）
         ページ-->>ブラウザ: 新しい習慣が入った今日の画面を返す
         ブラウザ-->>ユーザー: モーダルを閉じ、今日の画面を表示する
      else 入力が不正だった
         仮API-->>ページ: どの項目が不正かを返す
         ページ-->>ブラウザ: エラーを付けてモーダルを返す
         ブラウザ-->>ユーザー: モーダルのままエラーを表示する
      else ログインが切れていた
         仮API-->>ページ: ログインしていないことを返す
         ページ-->>ブラウザ: ログイン画面へ移るように返す
         ブラウザ-->>ユーザー: ログイン画面を表示する
      end
   end
```

- モーダルを開くときに仮APIへ頼まない理由
  開いたばかりのモーダルは空のフォームで、仮APIから取ってくるものがないから。
- 作ったあとに今日の習慣の一覧をもう一度頼む理由
  「今日の画面を開く」と同じ頼み方を使い回せて、一覧の正しさは仮APIにまかせられるから。
- 「1年後の自分」に紐づけるを扱わない理由
  紐づく先の「1年後の自分」をフェーズ1で作らないから。

### 「習慣の詳細を見る」 シーケンス図

- 前提：ログイン済み、今日の画面が表示されている（「今日の画面を開く」の図の終わり）
- 終わりの状態：
  - 習慣があった: 習慣の詳細の画面に、基本情報と数字が表示されている
  - 習慣が見つからない: 「習慣が見つかりません」の画面
  - ログインが切れていた: ログイン画面
- 表示する項目：
  - 基本情報: 名前、頻度、時間帯、所要時間
  - 数字: 達成率（直近30日）、現在の連続、最長の連続、累計、開始からの日数、継続カレンダー（直近12週）
- フェーズ1で扱わない部品：編集、今日の記録をつける、一時停止する、この習慣を削除、最近の記録、「1年後の自分に紐づけ済み」
- 図で省くもの：サイドバーのユーザー名とプラン（「今日の画面を開く」と同じ頼み方）

```mermaid
sequenceDiagram
   actor ユーザー
   participant ブラウザ
   participant ページ
   participant 仮API
   ユーザー->>ブラウザ: 今日の一覧で習慣を押す
   ブラウザ->>ページ: 習慣の詳細の画面をリクエストする（習慣のIDとログインの印を付けて）
   ページ->>仮API: ログインしている人のこの習慣を頼む（習慣のIDを渡す）
   alt ログインが切れていた
      仮API-->>ページ: ログインしていないことを返す
      ページ-->>ブラウザ: ログイン画面へ移るように返す
      ブラウザ-->>ユーザー: ログイン画面を表示する
   else 習慣が見つからない
      仮API-->>ページ: 見つからないことを返す
      ページ-->>ブラウザ: 「習慣が見つかりません」の画面を返す
      ブラウザ-->>ユーザー: 「習慣が見つかりません」と表示する
   else 習慣があった
      仮API-->>ページ: 習慣の基本情報を返す（名前・頻度・時間帯・所要時間）
      ページ->>仮API: この習慣の記録の集計を頼む（習慣のIDを渡す）
      仮API-->>ページ: 集計を返す（達成率・現在の連続・最長の連続・累計・開始からの日数・直近12週のカレンダー）
      ページ-->>ブラウザ: 基本情報と数字が入った習慣の詳細の画面を返す
      ブラウザ-->>ユーザー: 習慣の詳細の画面を表示する
   end
```

- 他の人の習慣も「見つからない」と返す理由
  他の人の習慣のIDを開かれても、その習慣があるかどうかを知られないようにするため。
- 基本情報と集計を分けて、順番に頼む理由
  習慣が見つからなければ集計は要らないから。集計は記録から計算するので、基本情報だけ欲しい場面と分けておける。
- 集計を仮APIが計算する理由
  ページが記録を全部受け取って計算しなくて済み、「今日」をどこで決めるかも1か所にまとまるから。
- 記録が0件でも数字は0を返す理由
  「空の一覧」と同じで、null の確認を忘れて画面が落ちるのを防ぐため。
- 「今日」を誰が決めるか（達成率と連続に効く）
  未決。API 契約で決める。
