## このファイル本書の目的

実装者とレビュー者が共通認識を合わせるために作成する。

## 列の定義

- ID、観点、前提、操作、期待結果
  上記で定義している。
- ID: 「画面の接頭辞、層の記号（C/E）、2桁の連番」例）LOGIN-C01
- 観点: 「どこを見ているか？」例）見出し
- 前提: テストを始める前の状態。例）ログイン中など
- 操作: ボタンを押すなど、操作するものを記載する。
- 期待結果: 操作後の結果、どうなるか？ってことを記載する。

## テストの分け方

- コンポーネントテストとE2Eテストを分けて記載する。
  例を以下に示す。

### コンポーネントテスト

| ID     | 観点   | 前提 | 操作     | 期待結果        |
| ------ | ------ | ---- | -------- | --------------- |
| TOP-02 | 見出し | なし | 描画する | h1が1つだけある |

### E2E

| ID     | 観点       | 前提 | 操作      | 期待結果                         |
| ------ | ---------- | ---- | --------- | -------------------------------- |
| TOP-03 | キーボード | なし | Tabを押す | 最初のリンクにフォーカスが当たる |

## 設計から実装までの流れ

### フロー図

```mermaid
sequenceDiagram
   actor 開発者
   participant AI
   participant Github
   participant CI
  開発者->>開発者: .penで作成されている画面を見て観点表を記載
  開発者->>AI: 観点表をレビュー依頼
  AI->>AI: 観点表のレビュー
  AI->>開発者: 観点表を確認する
  開発者->>AI: 観点表からテスト実装依頼
  AI->>AI: 観点表からテストを下書き
  AI->>開発者: テストの下書きをレビュー
  開発者->>AI: 問題ないことを確認したら実装依頼を行う
  AI->>AI: テスト実装を行う。
  AI->>開発者: 赤（テストが落ちること）と赤の理由を通知する。
  開発者->>開発者:赤（テストが落ちること）と赤の理由を確かめる。
  AI->>開発者: 確かめたものをテストが観点表と1対1か、仕様として読めるかレビューする
  AI-->>開発者: 実装して緑（テストが通っていること）にする
  CI->>CI:型チェック、lint、テスト、E2Eを流す
  CI->>github:問題がないことを通知する
  開発者->>開発者: 学習ログを記載
  開発者->>github: push
  github->>github: マージ
```
